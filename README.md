# Попутчики

Рабочее приложение на русском: Python 3.9+ (стандартная библиотека), SQLite, HTML/CSS/JavaScript. Установка npm и сторонних Python-пакетов не нужна.

## Запуск

В терминале откройте папку `poputchiki` и выполните:

```sh
python3 server.py
```

Откройте http://localhost:8000. Зарегистрируйтесь, создайте поездку, добавьте взнос или расход. Первый запуск создаёт `travel.sqlite3`. Все аккаунты и поездки сохраняются между перезапусками. Для резервной копии остановите сервер и скопируйте этот файл. Не размещайте базу в каталоге `static`.

Для телефона в одной доверенной Wi-Fi сети:

```sh
HOST=0.0.0.0 python3 server.py
```

На телефоне откройте `http://IP-адрес-компьютера:8000`. Приглашения нужно создавать по этому адресу, а не через localhost. Все участники регистрируются на одном сервере; их аккаунты и операции действительно общие.

Для постоянного доступа нужен сервер с постоянным диском, Python, обратный прокси с HTTPS и резервное копирование. После настройки HTTPS запускайте с `COOKIE_SECURE=1`. Встроенный HTTP-сервер предназначен для локального использования и демонстрации; перед открытым интернет-развёртыванием нужны ограничение частоты запросов, срок сессий, подтверждение почты и восстановление пароля. Эти функции сейчас не реализованы. Подключения к Sites не требуется: приложение не опубликовано на его хостинге, который не исполняет этот Python-сервер.

Переменные окружения: `HOST` (по умолчанию 127.0.0.1), `PORT` (8000), `TRAVEL_DB` (путь к SQLite), `COOKIE_SECURE` (1 для HTTPS).

## Что работает

- Регистрация, вход и выход. Пароли — PBKDF2-HMAC-SHA256, 600 000 итераций, индивидуальная соль. Сессия в HttpOnly/SameSite cookie; проверяется Origin для запросов браузера.
- Выбор страны и города из списка популярных направлений, выбор валюты по коду и названию. При выборе страны подставляется местная валюта; её можно изменить. Страна и город сохраняются в SQLite; старые базы обновляются автоматически без потери поездок. Справочник: `static/destinations.json`.
- Несколько поездок, 1–10 зарегистрированных участников, одноразовые приглашения по ссылке или коду. При привязке к email проверяется совпадение адреса аккаунта (сам адрес пока не верифицируется).
- Все участники добавляют расходы; автор может редактировать и удалять свои расходы. Удаление подтверждается в интерфейсе. Автор и плательщик независимы.
- Касса: взносы, оплата, явный возврат остатка. Недостаток средств блокируется сервером. Взносы и возвраты в расход не входят.
- Подгруппы, равные доли с распределением остатка копеек, индивидуальные доли в основной валюте, собственные категории, дата, комментарий и чек JPG/PNG/WebP до 3 МБ.
- Валютные расходы с сохранёнными исходной суммой, валютой и ручным курсом. Старый курс не меняется сам. Взносы/возвраты/остаток — только в основной валюте. Основная валюта фиксируется при создании поездки.
- Итоговые балансы, частичные возвраты, перевод в счёт общего баланса по нескольким расходам, два статуса «Отправил»/«Получил». Ожидающие суммы резервируются. Повторное подтверждение блокируется. Изменения, нарушающие резерв, запрещаются.
- Серверная защита приватных трат: чужие записи не выдаются, не включаются в историю, общую аналитику и уведомления. Приватные чеки передаются только внутри авторизованного ответа владельцу.
- Девять разделов интерфейса, фильтры, аналитика категорий/дней, раздельные рейтинги долей и личных оплат, история с автором, временем и значениями до/после.
- Уведомления в приложении и их настройки: приглашение зарегистрированному пользователю, новая/изменённая операция, отправка/подтверждение возврата. Обновляются при загрузке разделов и после действий; realtime-подписки нет.

## Модель расчётов

Все расчёты выполняются целыми копейками (поддерживаются валюты с двумя десятичными разрядами). Для иных валют требуется адаптировать точность.

`Баланс = взносы + общие оплаты личными деньгами − доли в общих расходах − выведенные из кассы деньги + подтверждённые отправленные переводы − подтверждённые полученные переводы`.

Сумма балансов всегда равна остатку кассы. Положительный баланс включает право на оставшиеся в кассе деньги: это не обязательно долг другого участника. Перевод между участниками разрешён только от отрицательного баланса к положительному. Остаток кассы возвращается отдельным явным действием в пределах положительного баланса участника.

Пример: Анна внесла 6 000 ₽, Борис 2 000 ₽. Ужин на двоих 4 000 ₽ из кассы даёт балансы +4 000 ₽ и 0 ₽; касса 4 000 ₽. Возврат Анне 4 000 ₽ обнуляет кассу и балансы. Если четверо из десяти делят 1 000 ₽, только их балансы уменьшаются на 250 ₽. При личной оплате плательщику добавляется 1 000 ₽. Остальные шесть не участвуют в расходе.

## Границы реализации

- В деталях личной оплаты доли и расчётное покрытие переводами показаны отдельно. Распределение подтверждённых переводов по расходам выполняется для отображения по датам, а не хранится как отдельный реестр обязательств. Взаимные зачёты и вклад кассы отражены в итоговом балансе. Для кассовых расходов показаны доли и ссылка на итоговый баланс. Строгая привязка каждого перевода к нескольким конкретным обязательствам с неизменяемыми идентификаторами ещё не реализована.
- Не реализовано автоматическое получение исторических курсов; ввод курса ручной и явный.
- Email/SMTP сервис не подключён; письма не отправляются. Ссылку организатор передаёт самостоятельно. Нет push-уведомлений.
- Участники приглашаются как реальные аккаунты; заранее создавать неавторизованные именные места и удалять участников с финансовой историей нельзя.
- Нет отмены ожидающего перевода и корректирующих проводок взносов/возвратов; эти движения не удаляются. Согласованность важнее редактирования движений задним числом.
- История выдаётся для последних 200 изменений, уведомления — последних 100. Нет пагинации/экспорта. Чеки хранятся внутри SQLite в base64; для большого объёма стоит подключить объектное хранилище.

## Проверка

```sh
python3 -m unittest -v test_app.py
```

Интеграционный сценарий поднимает временный сервер с отдельной базой. Проверяет регистрацию 11 аккаунтов, лимит 10 участников, поездку с одним участником, подгруппу 4 из 10, равные/индивидуальные доли, взносы разного размера, недостаток кассы, валютный расход, изменение участников, приватность чтения и удаления, частичный возврат, запрет подтверждения отправителем и повторного подтверждения, отсутствие двойного счёта и равенство суммы балансов кассе.

JavaScript дополнительно проверяется `node --check static/app.js`, если установлен Node.js.
